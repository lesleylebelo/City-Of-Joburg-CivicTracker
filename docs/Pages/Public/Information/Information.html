CivicTrack is an independent student project built to help people in Johannesburg report municipal issues and follow their progress. It is not an official City of Johannesburg service and is not endorsed by the City.

How reporting works

  1. Create a resident account and sign in when a working application service is available.
  2. Choose a category, describe the issue and select its location. You can add a photo.
  3. Open your issue history to check the status and any administrator notes.

Prototype status: this GitHub Pages site is a static demonstration. Sign-in and report submission require a separately running application service. Reports in the project are not sent to the City and may not be acted on.

For a municipal service request, use the City’s official reporting channels.

Frequently asked questions

Is CivicTrack an official City service?

No. It is an independent student project. The City name identifies the community this project is about. The landing page uses its own CivicTrack mark; City branding in the project’s existing imagery does not imply endorsement or partnership.

Why can’t I sign in on this public site?

GitHub Pages serves the static demonstration. Account and reporting features need a running application service, which is separate from this public site.

Will submitting here send a report to the City?

No. Reports are stored within the project application when that service is running. There is no connection that forwards them to the City. Use Joburg Connect for official faults and enquiries.

Can I report an emergency?

An app report is not an emergency call. For life-threatening emergencies, call 011 375 5911. For general City enquiries and faults, call 0860 562 874. Check the City’s current contact details.

Privacy & data use

This notice describes the current prototype. It is not a certification of compliance with the Protection of Personal Information Act (POPIA). Use sample information when trying the prototype and avoid sensitive personal details in descriptions or photos.

What information the application collects

  • Issue reports: title, category, priority, description, issue address, selected coordinates and an optional photo.
  • Resident accounts: name, email address, phone number and a password stored as a hash. The browser stores a sign-in token and basic account information after a successful login.
  • Technical data: the landing page has no analytics scripts. GitHub Pages logs visitor IP addresses for security, as described in GitHub’s hosting documentation. Social and City links take you to separate services.

Why the application uses it

Account information supports sign-in and associates reports with a resident. Report details are used to display issue history and let project administrators review reports and update their status. Address searches are sent to OpenStreetMap’s Nominatim service to suggest locations.

Who can see it

The administrator portal retrieves report information and resident names, email addresses and phone numbers. Uploaded photos are served through direct URLs and may be accessible to anyone with the link. Do not include identity documents, private contact details or other sensitive information in uploaded content.

How long it is kept and how to request changes

The current project has no automatic retention schedule. Records remain in the application database until deleted. When the application service is running, residents can edit or delete their own pending reports through issue history.

To request a correction or deletion beyond those controls, contact the project maintainer through GitHub Issues and ask for a private contact method. GitHub Issues is public: do not post personal information there.

For information about POPIA, see the Information Regulator’s copy of POPIA (PDF).

Terms of use

CivicTrack is a student prototype for demonstration and learning. It is not an official municipal reporting channel. Do not rely on it for emergency assistance, an official reference number, a municipal response or a guaranteed repair.

Submit only content you are entitled to share. Keep descriptions relevant to the issue, avoid other people’s personal information and use official City channels for requests that require municipal action.

These project-use notes describe the prototype’s limits; they do not replace the City’s own processes or the terms of external services.

Accessibility

The public pages include keyboard-accessible links, visible focus states, a skip-to-content link, responsive layouts and reduced-motion support. This is not a claim of full accessibility certification.

If a part of the site is difficult to use, report it to the project maintainer. Include the page, the task you were trying to complete and any browser or assistive-technology details you are comfortable sharing.
